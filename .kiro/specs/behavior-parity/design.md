# Design

FastAPI validates API inputs and prepares a batch of integers. A bounded subprocess executes the original GW-BASIC fixture in a headless PC-BASIC session. The service checks the prompt sequence and fee output, then compares each fee with the selected Python port. A React workbench displays the evidence and generates developer-reviewed text and pytest snippets from an observed mismatch.

The fixed source file is the only BASIC program the server runs. Both actions share the same runtime adapter and execution failure handling. The deployment serves the compiled frontend and the API from the same container.

Version 2 registers trusted local scalar cases through cases.json. INPUT X and END delimit each source program. A generated FOR/GOSUB driver supplies X and invokes the policy statements in one interpreter process. Both endpoints call run_case with lower and upper bounds. Reports use actual BASIC output and include provenance hashes and all comparisons. The UI loads labels and bounds through GET /api/cases.
